# T1703 - Minimale Multi-Selector

## Status

Uitgevoerd. Checkpointreview verplicht voordat T1704 start.

## Doel

Bereid een minimale multi-materieel selector voor zonder library, zonder package en zonder de bestaande single-resource flow te breken.

## Afhankelijkheid

T1701 en T1702 moeten afgerond zijn. Het checkpoint na T1701 moet expliciet goedgekeurd zijn.

## Ontwerprichtlijn

De selector moet meerdere materieelitems in 1 open flow kunnen kiezen.

Daarom:

- selector blijft open tijdens meerdere keuzes;
- resultaten zijn togglebaar;
- gekozen items staan in een selected summary;
- per item wissen is mogelijk;
- alles wissen is mogelijk;
- `Klaar` sluit de selector;
- `Klaar` is geen server-save.

## In Scope Voor Latere Implementatie

- multi-select gedrag zonder library;
- selected summary met compacte nummerbadges;
- wissen per geselecteerd materieelitem;
- `Alles wissen`;
- `Klaar` als sluitactie;
- zoek/filterfunctionaliteit behouden;
- edit mode met bestaande directe lokale update behouden;
- create mode met bestaande submitflow behouden;
- single-resource flow niet regressief maken.

## Buiten Scope

- multi-select library;
- package install;
- popover/modal-framework;
- drag/drop binnen selector;
- resource CRUD/import;
- bulkplanning;
- availability-integratie;
- persistence;
- save/cancel semantiek;
- volledige sticky-form redesign.

## UX-Regels

Selected summary:

- toont gekozen materieel compact;
- gebruikt nummers als primaire identificatie;
- lange namen worden getruncate;
- summary mag de sticky form niet hoog maken.

Resultaten:

- klik op ongekozen item voegt toe;
- klik op gekozen item mag verwijderen of duidelijk geselecteerde staat tonen;
- geselecteerde staat moet scanbaar zijn zonder checkbox-library.

Wissen:

- per item wissen triggert geen form submit;
- alles wissen triggert geen form submit;
- selector blijft open na wissen.

Sluiten:

- `Klaar` sluit de selector;
- keuze is al lokaal bijgewerkt;
- geen server-save of persistence-belofte.

## Acceptance Criteria Voor Latere Implementatie

- meerdere materieelitems kunnen gekozen worden;
- gekozen items zijn compact zichtbaar;
- per-item wissen werkt;
- alles wissen werkt;
- selector blijft open tijdens meerdere keuzes;
- `Klaar` sluit de selector;
- planning zonder materieel blijft mogelijk;
- 1 materieelitem blijft even eenvoudig als vandaag;
- bestaande single-resource flow is niet gebroken;
- build slaagt;
- localhost-regressie op create en edit slaagt.

Na T1703 stopt implementatie voor review.

Te reviewen:

## Risico's

- selected summary kan te veel verticale ruimte nemen;
- `Klaar` kan als saveknop worden begrepen;
- single-resource auto-collapse uit Sprint 13 kan onbedoeld verloren gaan;
- per-item wissen kan te kleine klikdoelen krijgen;
- directe editupdates met meerdere toggles kunnen onduidelijk worden;
- selector kan meer aandacht opeisen dan taak/project.

## Uitgevoerd

- bestaande `ResourceSelector` voorzichtig aangepast naar multi-select zonder library;
- selected summary toegevoegd met compacte gekozen materieelchips;
- toggle aan/uit per resultaat toegevoegd;
- wissen per gekozen materieelitem toegevoegd;
- `Alles wissen` toegevoegd;
- `Klaar` toegevoegd als lokale sluitactie;
- selector blijft open tijdens meerdere keuzes;
- zoek/filterfunctionaliteit behouden;
- create mode ondersteunt 0..n materieelitems;
- edit mode ondersteunt directe lokale update van 0..n materieelitems;
- `PlanningForm` gebruikt `getPlanningItemResourceIds(item)` voor edit-prefill;
- create en edit schrijven via `withPlanningItemResourceIds`;
- `resourceId` blijft primary mirror voor backwards compatibility;
- geen conflictservicewijzigingen uitgevoerd;
- geen packages of multi-select library toegevoegd;
- geen availability-wijzigingen uitgevoerd;
- geen brede contractrename uitgevoerd.

## Validatie

- `npm run build` geslaagd;
- helper/mirror sanity-check geslaagd;
- localhost-smoke geslaagd voor planning zonder materieel;
- localhost-smoke geslaagd voor planning met 1 materieelitem;

## Checkpointobservatie

- Selector blijft compact genoeg voor deze slice;
- selected summary is scanbaar, maar kan bij veel gekozen materieelitems nog hoogte vragen;
- `Klaar` sluit lokaal en heeft geen save/persistence-semantiek;
- single-resource flow blijft bruikbaar, maar auto-collapse na 1 keuze is bewust vervangen door `Klaar` omdat multi-keuze open moet blijven;
- conflictvalidatie blijft tijdelijk single-resource tot T1704.
