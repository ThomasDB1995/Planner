# T1004 - QA, Scopecontrole En Sprint Closure

## Status

Uitgevoerd.

## Doel

Valideer de volledige Sprint 10-slice en sluit de sprint pas af wanneer create, edit, delete, relocation en conflictvalidatie samen blijven werken.

## Scope

- build uitvoeren;
- localhost controleren;
- create-flow regressie controleren;
- edit-flow controleren;
- resource-edit en conflictvalidatie controleren;
- delete na edit controleren;
- relocation na edit controleren;
- scopecontrole uitvoeren;
- `QA.md`, `SPRINT.md` en `PROJECT_STATE.md` bijwerken bij closure.

## Out-of-Scope

- nieuwe features toevoegen tijdens closure;
- inline editor;
- drag/drop;
- persistence/backend/API;
- server-autosave;
- undo/history;
- packages/frameworks;
- availability;
- multi-resource;
- grote redesign.

## Files

Waarschijnlijk:

- `sprints/sprint-10-planning-card-editing-quick-adjustments/QA.md`
- `sprints/sprint-10-planning-card-editing-quick-adjustments/SPRINT.md`
- `PROJECT_STATE.md`

## Implementatiestappen

1. Run `npm run build`.
2. Start localhost.
3. Voer de Sprint 10 test matrix uit.
4. Controleer browserconsole.
5. Controleer out-of-scope lijst.
6. Werk QA-resultaten bij.
7. Werk sprintresultaat bij.
8. Werk `PROJECT_STATE.md` bij.
9. Rapporteer open risico's en handmatige QA-punten.

## Acceptance Criteria

- build slaagt;
- localhost rendert;
- create-flow werkt;
- edit-flow werkt;
- resource-edit herberekent conflicten;
- edit mode naar create mode blijft duidelijk genoeg;
- delete na edit werkt;
- relocation na edit werkt;
- geen out-of-scope features toegevoegd;
- documentatie is bijgewerkt.

## Testaanpak

Gebruik de test matrix uit Sprint 10 `QA.md`.

## Regressierisico's

- QA dekt create-flow onvoldoende na editwijzigingen.
- Relocation na edit wordt vergeten.
- Scope creep wordt tijdens polish alsnog toegevoegd.

## Rollback

Geen rollback van werkende feature zonder expliciete opdracht. Bij regressie: documenteer fout, stop uitbreiding en vraag architectbeslissing.

## Resultaat

T1004 is uitgevoerd als QA, scopecontrole en sprint closure.

Build:

- `npm run build` geslaagd;
- TypeScript-validatie geslaagd;
- Next.js static page generation geslaagd.

Localhost:

- `http://127.0.0.1:3000` geopend;
- applicatietitel zichtbaar;
- planningformulier zichtbaar;
- weekmatrix zichtbaar;
- maandag tot vrijdag zichtbaar;
- browserconsole zonder warnings of errors.

Closure-validatie op basis van T1003 en T1004 smoke:

- edit mode openen werkt;
- taak/project direct wijzigen werkt;
- resource kiezen en wissen werkt;
- conflictvalidatie herberekent na resourcewijziging;
- datum/werknemer zijn disabled in edit mode;
- create mode na edit mode werkt;
- create/edit scheiding is verbeterd door de T1003 guardrail;
- selected card blijft behouden voor relocation terwijl actieve cel/create context kan wijzigen;
- delete na edit werkt;
- relocation na edit werkt.

Open UX-punten:

- directe lokale edit heeft nog geen undo/redo;
- selected card kan zichtbaar blijven terwijl het formulier terug in create mode staat;
- bezette doelcel ambiguity uit Sprint 08 blijft open;
- toekomstige server-backed persistence vereist later een aparte infrastructure sprint.

Scopecontrole:

- geen inline editor toegevoegd;
- geen drag/drop toegevoegd;
- geen persistence/backend/API toegevoegd;
- geen server-autosave toegevoegd;
- geen undo/redo toegevoegd;
- geen packages/frameworks toegevoegd;
- geen multi-resource toegevoegd;
- geen availability toegevoegd;
- geen redesign toegevoegd;
- geen save/cancel-flow toegevoegd.

Closure-conclusie:

Sprint 10 is afgerond als kleine Planning Card Editing & Quick Adjustments slice. Bestaande planningcards kunnen via het bestaande `PlanningForm` direct lokaal aangepast worden voor taak/project en optionele resource, met behoud van create-flow, delete, relocation en conflictvalidatie.
