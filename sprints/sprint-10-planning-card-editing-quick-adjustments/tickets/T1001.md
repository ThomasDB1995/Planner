# T1001 - Edit-Flow Plan En Statecontract

## Status

Uitgevoerd.

## Doel

Bepaal de kleinste veilige edit-flow voor bestaande planningcards via het bestaande `PlanningForm`.

## Scope

- huidige selected-card, selected-cell en destination-cell stateflow inspecteren;
- edit target bepalen op basis van `selectedCard.planningItemId`;
- create/edit-modus expliciet benoemen;
- updatecontract bepalen:
  - update exact 1 `PlanningItem`;
  - behoud `id`;
  - behoud bestaande velden tenzij expliciet aangepast;
  - conflictvalidatie blijft afgeleid uit `planningItems`;
- regressierisico's benoemen voor create, celselectie, delete en relocation.

## Out-of-Scope

- code wijzigen zonder goedgekeurd plan;
- inline editor;
- drag/drop;
- packages/frameworks;
- backend/API/database/persistence;
- autosave;
- undo/history;
- multi-resource;
- availability;
- contextmenu;
- grote redesign.

## Files

Waarschijnlijk relevant:

- `src/app/page.tsx`
- `src/components/planning/PlanningForm.tsx`
- `src/components/planning/PlanningCard.tsx`

## Implementatiestappen

1. Lees Sprint 10 `SPRINT.md`.
2. Inspecteer `page.tsx` voor `planningItems`, `selectedCard`, `selectedCell` en `activeDestinationCell`.
3. Inspecteer `PlanningForm` create-flow en form state.
4. Beschrijf hoe het geselecteerde planningitem als edit target wordt doorgegeven.
5. Beschrijf hoe `onUpdate` exact 1 item wijzigt.
6. Beschrijf hoe create en edit zichtbaar verschillen.
7. Benoem QA-risico's voor T1002 t/m T1004.
8. Wacht op expliciete goedkeuring voor codewijzigingen.

## Acceptance Criteria

- plan gebruikt bestaande local state;
- plan hergebruikt het bestaande `PlanningForm`;
- plan introduceert geen inline editor of modalverplichting;
- plan behoudt item-id bij update;
- plan benoemt create/edit-scheiding;
- plan benoemt annuleren zonder mutatie;
- plan benoemt conflictvalidatie via bestaande `planningItems` flow.

## Testaanpak

- `npm run build` uitgevoerd.
- Localhost gecontroleerd op `http://127.0.0.1:3000`.
- Planningitem aangemaakt.
- Geselecteerde card geopend in editmodus.
- Bestaande waarden in `PlanningForm` gecontroleerd.
- Create mode na celselectie gecontroleerd.
- Relocation na editmode-check gecontroleerd.
- Delete na editmode-check gecontroleerd.

## Regressierisico's

- Formuliermodus wordt onduidelijk.
- Celselectie overschrijft editvelden.
- Selected card en active destination cell raken semantisch vermengd.
- Update wordt onbedoeld delete+create.

## Rollback

Plan/documentatie terugzetten indien de architect een andere edit-richting kiest.

## Resultaat

T1001 is uitgevoerd als minimale editmode-checkpoint implementatie:

- `editingPlanningItemId` state toegevoegd in `page.tsx`;
- cardselectie zet `selectedCard` en opent dezelfde card als edit target;
- celselectie schakelt het formulier terug naar create mode en behoudt selected card voor relocation;
- delete wist `editingPlanningItemId` wanneer de bewerkte card wordt verwijderd;
- `PlanningForm` onderscheidt create mode en edit mode;
- edit mode vult datum, werknemer, taak/project en optionele resource vanuit de geselecteerde planningcard;
- edit mode toont bewust geen actieve save/update-flow;
- de editknop is disabled met label `Opslaan later`;
- create-submit blijft bestaande `onCreate` gebruiken;
- er is geen update van `planningItems` toegevoegd.

Validatie:

- `npm run build` geslaagd;
- localhost opent;
- card openen in edit mode werkt;
- formulier toont bestaande waarden;
- create mode blijft werken na celselectie;
- selected card blijft bruikbaar voor relocation;
- relocation blijft werken via `Verplaats naar actieve cel`;
- delete blijft werken na editmode-check;
- geen browserconsole-warnings of -errors gezien.
