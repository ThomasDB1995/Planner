# T704 - Relocation Discovery Note

## Doel

Documenteer hoe latere relocation waarschijnlijk werkt, zonder move UI of drag/drop te bouwen.

## Scope

- beschrijven wat verplaatsen betekent in huidig model;
- benoemen dat relocation `employeeId` en/of `date` van een bestaand `PlanningItem` wijzigt;
- benoemen dat conflictvalidatie na relocation opnieuw moet draaien;
- open UX-vragen vastleggen;
- expliciet noteren dat echte drag/drop discovery-only blijft.

## Out-of-Scope

- code wijzigen;
- move-knoppen;
- drag/drop;
- keyboard relocation;
- contextmenu;
- undo/history;
- persistence/backend/API;
- collision/overlap-regels;
- multi-resource conflictregels;
- availability-regels implementeren;
- architectuuruitbreiding.

## Verwachte Files

- `sprints/sprint-07-planningcard-interaction-discovery/SPRINT.md`
- `sprints/sprint-07-planningcard-interaction-discovery/QA.md`
- mogelijk `docs/Planning_UX_Domain_Findings.md`
- mogelijk `PROJECT_STATE.md` bij sprint closure

## Implementatiestappen

1. Lees de sectie `Praktijkvalidatie Planningcard-Manipulatie` in `docs/Planning_UX_Domain_Findings.md`.
2. Beschrijf de minimale state-impact van relocation.
3. Beschrijf mogelijke latere UX-richtingen:
   - geselecteerde card verplaatsen via compacte actie;
   - gekozen doelcel na selectie;
   - later pas drag/drop evalueren.
4. Noteer open vragen over conflictvalidatie, availability en multi-resource.
5. Bevestig dat Sprint 07 geen relocation UI bouwt.
6. Bevestig dat drag/drop en packages buiten scope blijven.

## Acceptance Criteria

- relocation is als latere stap concreet genoeg beschreven;
- er is geen code gewijzigd;
- er is geen move UI voorgesteld als onderdeel van Sprint 07;
- drag/drop blijft expliciet discovery-only;
- availability blijft doorgeschoven;
- vervolgvragen zijn duidelijk vastgelegd.

## Testaanpak

- Review-only.
- Geen build.
- Geen localhostcontrole.
- Controleer documentatie op scopelekken.

## Regressierisico's

- Discoverytekst wordt te concreet en leest als implementatie-opdracht.
- Move UI sluipt in T703 mee.
- Drag/drop-packagekeuze wordt te vroeg gemaakt.
- Availability of multi-resource wordt vermengd met relocation.

## Rollback

- Draai alleen de documentatienotitie terug of herschrijf deze scherper.
- Geen code-impact.

## Codex-risico

Codex kan relocation alvast implementeren omdat delete en selectie state aanwezig zijn. Niet doen: T704 is documentatie en besluitvoorbereiding.
