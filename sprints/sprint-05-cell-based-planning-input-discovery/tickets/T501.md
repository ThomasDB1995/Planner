# T501 - Cell Interaction Discovery En Minimale UX-Keuze

## Doel

Bepaal en documenteer de kleinste interactie waarmee een planner een werknemer + datum cel kan selecteren als startpunt voor planninginvoer.

## Context

Sprint 04 is afgesloten. De huidige planning is technisch werkend, maar invoer loopt nog via een centraal formulier. Sprint 05 verschuift de UX richting celgebaseerde planning.

## Scope

- inspecteer de bestaande weekplanningcomponenten;
- bepaal welke component de celinteractie moet dragen;
- kies een minimale selectiestaat voor werknemer + datum;
- beschrijf hoe de geselecteerde cel zichtbaar wordt;
- beschrijf hoe de bestaande invoerflow hergebruikt kan worden;
- leg open UX-beslissingen vast.

## Buiten Scope

- implementatie van drag/drop;
- nieuwe domeinentiteiten;
- materialen/artikelen bouwen;
- transportmiddelbeheer;
- nieuwe packages of frameworks;
- database, backend, import of CRUD.

## Verwachte Bestanden

Mogelijke documentatie:

- `docs/Planning_UX_Domain_Findings.md`
- `sprints/sprint-05-cell-based-planning-input-discovery/QA.md`

Als code pas in dit ticket wordt aangepast, moet dat vooraf expliciet worden goedgekeurd.

## Acceptance Criteria

- minimale celinteractie is beschreven;
- benodigde componenten zijn benoemd;
- gekozen aanpak hergebruikt bestaande planningstate;
- risico's voor scanbaarheid zijn benoemd;
- geen architectuuruitbreiding is voorgesteld als noodzakelijke eerste stap.

## Verificatie

- Scopecontrole tegen `SPRINT.md`.
- Check dat discovery geen out-of-scope bouwopdracht introduceert.

## Risico's

- Te vroeg meerdere view modes ontwerpen.
- Celinteractie verwarren met drag/drop.
- Te veel informatie in een cel willen tonen.

## Codex Werkwijze

Geen codewijziging zonder expliciet goedgekeurd plan.
