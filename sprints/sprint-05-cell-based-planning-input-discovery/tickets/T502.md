# T502 - Celcontext Koppelen Aan Compacte Planninginvoer

## Doel

Maak een kleine lokale UX-slice waarin invoer start vanuit een geselecteerde werknemer + datum cel.

## Context

De bestaande `PlanningForm` kan planningitems aanmaken, maar vraagt datum en werknemer los van de matrix. Dit ticket brengt die context dichter naar de cel zonder de resource- of conflictflow te vervangen.

## Scope

- maak planningcellen selecteerbaar of klikbaar;
- houd geselecteerde `employeeId` en `date` lokaal bij;
- toon geselecteerde werknemer en datum duidelijk bij de invoer;
- vul werknemer en datum automatisch vanuit de celcontext;
- behoud invoer voor taak/project, resource en status;
- hergebruik de bestaande `ResourceSelector`;
- maak het item na submit zichtbaar in de gekozen cel;
- behoud bestaande conflictvalidatie.

## Buiten Scope

- drag/drop;
- bulk editing;
- edit/delete van bestaande planningitems;
- materialen/artikelen;
- transportmiddelbeheer;
- nieuwe persistence;
- nieuwe resource-contracten;
- nieuwe packages.

## Acceptance Criteria

- gebruiker kan een cel kiezen;
- gekozen werknemer en datum zijn zichtbaar;
- toevoegen gebruikt automatisch de gekozen celcontext;
- taak/project en resource blijven verplicht;
- status blijft beschikbaar;
- nieuw item verschijnt in de gekozen cel;
- dubbele resourceboeking en defecte resource waarschuwingen blijven werken;
- centrale formulierlogica is niet uitgebreid tot een nieuwe module.

## Testcases

| Scenario | Verwacht resultaat |
| --- | --- |
| Cel Jan + maandag selecteren | Invoercontext toont Jan en maandag |
| Item toevoegen vanuit gekozen cel | Item verschijnt in Jan/maandag cel |
| Geen cel geselecteerd | UI toont veilige lege of startstaat |
| Taak/project ontbreekt | Submit wordt geblokkeerd of duidelijke melding verschijnt |
| Resource ontbreekt | Submit wordt geblokkeerd of duidelijke melding verschijnt |
| Zelfde resource op zelfde datum | Conflictmelding blijft zichtbaar |
| Defecte resource kiezen | Defectwaarschuwing blijft zichtbaar |

## Verificatie

- `npm run build`
- localhost handmatig controleren
- regressie op bestaande resource selector
- regressie op conflict summary

## Risico's

- Formulier en celcontext kunnen dubbelzinnig worden.
- Cellen kunnen te druk worden als selectie, cards en acties tegelijk zichtbaar zijn.
- Centrale formulierlayout kan de matrix nog steeds te dominant maken.
